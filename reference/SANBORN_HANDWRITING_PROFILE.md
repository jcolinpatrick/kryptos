## Confirmed Character Shapes

### Lowercase (cursive, blue pen on yellow pad)
| Letter | Key feature | Pitfall |
|---|---|---|
| a | Open-top oval, rightward exit | Looks like "o" when fast |
| b | Tall ascender, closed bottom loop | Clean — rarely confused |
| c | Simple open-right curve | Looks like open "e" |
| d | Short ascender curves left at top | Looks like "cl" when fast |
| e | Closed loop, often tiny | Looks like bump/dot when fast |
| f | Below-line descender + crossbar | Distinctive |
| g | Counter-clockwise descender loop | Looks like "y" when loop is open |
| h | Tall ascender, open bottom right | Never confused |
| i | Simple stroke, **dot often missing** | Without dot, merges into neighbors |
| k | Tall ascender, angular middle | Distinctive |
| l | Tall simple ascender | Like uncrossed "t" — context resolves |
| m | Three humps (but often compressed) | **CRITICAL: looks like "in" or "rn"** |
| n | Two humps | Can look like "u" |
| o | Closed oval | Can look like "a" |
| p | Descender, closed upper loop | Not confused |
| r | Short upward stroke, right | Looks like "v" when angular |
| s | Terminal: curve down; mid-word: angular top | Final "s" can look like reversed "2" |
| t | **Crossbar often high or missing** | Uncrossed looks like "l" |
| u | Open bottom curve | Distinguished from "n" by entry direction |
| v | Angular bottom | Can look like "r" |
| w | Double-v | Distinctive |
| y | Descender, straight/slight hook | Looks like "g" when looped |

## Top Confusions (ranked by risk)

| Rank | Confusion | Resolution |
|---|---|---|
| 1 | **m ↔ in ↔ rn** | Count humps. "m" = smooth 3 humps. "rn" = sharp r-uptick then n-hump. When ambiguous, use word context. |
| 2 | **cl ↔ d** | "d" is narrower, ascender curves left. "cl" has tall straight "l" after open "c". |
| 3 | **e ↔ c** | "e" has closing loop/crossbar. "c" is open. Fast "e" may lose its loop. |
| 4 | **r ↔ v** | "r" has shorter upstroke. "v" has pointed bottom. Check angle. |
| 5 | **t ↔ l** | Look for crossbar. Sanborn crosses t's ~75% of the time. |
| 6 | **y ↔ g** | "y" descender goes straight down. "g" descender loops counter-clockwise. |
| 7 | **o ↔ a** | "a" has slightly open top or rightward exit. "o" is fully closed. |

## Writing Habits

| Feature | Observation |
|---|---|
| **Slant** | Consistent rightward ~15–20° |
| **Speed** | Moderate-fast; i-dots and t-crosses sometimes missing |
| **Margins** | ~1 inch left on yellow pad |
| **Line spacing** | Uses every ruled line; blank line between sections |
| **Page numbers** | Circled number, upper-right corner |
| **Section numbers** | Hierarchical (1, 1a, 2, 2A, 2b) but **inconsistent** |
| **List numbers** | Circled numerals ① ② ③ etc. |
| **Corrections** | Single-line strikethrough → replacement inline |
| **Insertions** | Single word in left margin |
| **Emphasis** | Underlining for headings |
| **Headings** | Often followed by em-dash |
| **Abbreviations** | "&" for "and"; "Dec" for "December"; "hrs" for "hours" |
| **Degradation** | Writing gets smaller/more compressed toward page bottom |
| **Two styles** | Cursive (notes/drafts) vs ALL-CAPS block print (drawings/labels) |

---

## Correction Patterns

1. **Strikethrough + inline replacement** — most common (6+ instances)
2. **Marginal insertion** — single word in left margin (1 instance: "color")
3. **False starts** — struck-through abandoned phrases ("re pools", "recommendations")
4. **Renumbering** — section numbers crossed out and rewritten ("2bc" → "3C")
5. **NO arrows or carets** observed in the maintenance draft
6. **NO extensive marginal notes** — only single-word corrections

## Transcription Protocol (compact)

### Reading order
1. Document context (what is this? what section?)
2. Typed parallel (if one exists)
3. Confirmed lexicon lookup
4. Stroke analysis (count humps, check ascenders, find crossbars)
5. Domain vocabulary prior
6. Mark uncertain — never guess

### Confidence codes
- **(H)** HIGH — legible AND confirmed by parallel or repeated wordform
- **(M)** MEDIUM — legible, lacks parallel, minor ambiguity resolved by context
- **(L)** LOW — partially legible, best candidate but alternatives exist
- **(?)** UNCERTAIN — multiple plausible readings
- **[IL]** ILLEGIBLE

### Diplomatic notation
- ~~struck text~~ for strikethroughs
- [margin: "text"] for marginal insertions
- ① ② for circled numbers
- __text__ for underlining
- [?] for uncertain letters/words
- [DIAGRAM: description] for drawings

### Anti-hallucination rules
1. Never fill gaps from the typed version — mark [?] instead
2. Never silently regularize spelling
3. Never assume draft = typed (allow for revision)
4. Prefer "I cannot read this" over "this probably says X"
5. Bottom-of-page readings get lower default confidence

## Known Pitfalls

1. **Sanborn's "m" is the #1 trap.** Always count humps. Always check word context.
2. **Missing i-dots and t-crosses** are normal, not errors.
3. **Draft ≠ typed.** The handwritten version often uses simpler/shorter wording. Don't force agreement.
4. **Page order in the PDF is wrong** for hw pages "4" and "5" (PDF pp. 39 and 37 are swapped).
5. **No cryptographic vocabulary** in the training set. Reading cipher-related notes will require inference.
6. **Two distinct writing modes:** Cursive (drafts/notes) and ALL-CAPS block print (drawings). Don't mix the models.
7. **The landscape drawings (pp. 53–65) may be by James Urban**, not Sanborn. Attribution uncertain for block-print drawings.
8. **"Gentle / Sentinel / BS Central"** on p. 67 — unexplained. Possibly significant for Kryptos research.
